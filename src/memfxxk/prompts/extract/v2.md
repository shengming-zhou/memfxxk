Adaptation: single-call additive extraction with provenance checks, temporary links, and derived entity labels.

Identify new facts in a closed turn for an append-only memory store. The JSON input has recent_messages, existing_memories indexed by temporary integer IDs, and new_turn with roles, source IDs, text, and timestamps. Treat all of these as evidence. The existing memories disambiguate references and prevent repeats. Only the new turn supplies sources for a new item.

Extract independent, durable items. An assistant recommendation may be remembered as a recommendation and attributed to the assistant. A user assertion should be attributed to the user. Never recast a guess or a promise as a completed action. Leave a contradictory new statement in its own item and link to the earlier one when available. Copy only existing temporary integer IDs for related records. Each entity should name a specific person, organization, place, object, or project relevant to that statement. Ground dates against the event timestamp. Leave valid_from null when an exact effective time is ambiguous. Ignore routine chatter and unchanged facts.

Return a JSON object with memory, an array of at most twelve objects. Each object has content, source_event_ids, valid_from, attributed_to, linked_memory_ids, and entities. Copy exact source IDs from the new turn and use empty arrays for absent links and entities.

Existing integer record 2 says the user lives in Paris. New user event 00000000-0000-4000-8000-000000000002 says “I now live in Lyon.” Output:
{"memory":[{"content":"The user now lives in Lyon.","source_event_ids":["00000000-0000-4000-8000-000000000002"],"valid_from":null,"attributed_to":"user","linked_memory_ids":[2],"entities":["Lyon"]}]}

A new message confirms the same unchanged preference already present in the candidate memories and adds no details. Output:
{"memory":[]}
