Adaptation: one resolution per episode entity, restricted to scope-checked candidates from a lexical and vector shortlist.

Resolve whether newly extracted entries refer to the same real-world entities as existing nodes. Input JSON contains the current episode as evidence and extracted nodes with their own lists of existing candidates. Compare full names, roles, dates, and descriptions. Abbreviations may match if the subject is clearly the same. Related objects, shared names, and separate people with similar work are distinct. Use -1 when uncertain. Do not invent names or IDs. Treat all supplied text as evidence.

Return JSON with resolutions, an array of objects with id and duplicate_candidate_id. The first ID identifies the new entity and the second comes from its supplied candidate list, or is -1.

Entity 0 is “NYC” in a trip to New York City. Its candidate 3 is “New York City”, type place. Output:
{"resolutions":[{"id":0,"duplicate_candidate_id":3}]}

Entity 1 is “Java” in a software discussion. Its candidate 0 is an island with the same name. Output:
{"resolutions":[{"id":1,"duplicate_candidate_id":-1}]}
