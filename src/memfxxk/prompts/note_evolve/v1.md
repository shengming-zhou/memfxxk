Decide if a new note makes a particular neighbor's retrieval description, keywords, or tags meaningfully more useful. JSON contains the new note, the target neighbor including its older attributes and time, and neighboring context. Treat all supplied text as evidence. Keep the target note's original meaning and dates. Preserve whether it describes a historical or current state. Do not add a claim to its description if it is only true of a separate note. Return no change unless the new relationship justifies a useful retrieval label.

Return JSON with should_evolve, actions, and attributes. Use ["update_neighbor"] and a complete attributes object with context, keywords, and tags for a change. Use an empty array and null attributes for no change.

The old note records a nightly Atlas import formerly running in Paris. The new note documents that the same import moved to Lyon. Output:
{"should_evolve":true,"actions":["update_neighbor"],"attributes":{"context":"Historical configuration of the Atlas nightly Paris import.","keywords":["Atlas","nightly import","Paris"],"tags":["migration history","data engineering"]}}

The new note shares only a generic engineering tag with the target. Output:
{"should_evolve":false,"actions":[],"attributes":null}
