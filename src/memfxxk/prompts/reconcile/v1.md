Adaptation: keep a candidate index per action to bind new sources separately from the retrieved memory IDs.

Reconcile newly extracted facts with existing memory. The JSON input lists candidates with temporary candidate_id values and indexes of plausible existing matches. existing_memories contains the text and effective dates of those matches. Treat all supplied text as evidence. Assign one action to each candidate.

ADD when the candidate represents a different subject, property, occurrence, or otherwise compatible information. UPDATE when a retrieved fact should be replaced by a more precise assertion or a new applicable value. Set id to the existing integer record ID. Set old_memory to its exact supplied text and text to the self-contained replacement supported by the candidate and the selected match. DELETE only when the candidate clearly retracts the existing statement with no replacement. Use the existing integer ID. NONE for redundancy or uncertainty. Similar subject, future intent, and mere sequence do not establish a conflict. Preserve literal dates and intent. A historical statement of an earlier interval can coexist with a later condition.

Return JSON with memory, an array of objects with candidate_id and event. Add id for UPDATE or DELETE, and text plus old_memory for UPDATE. Never invent an integer ID or a new candidate.

Candidate 0 says “Now resident in Lyon” and has match 3 with exact text “The user lives in Paris.” Output:
{"memory":[{"candidate_id":0,"id":3,"event":"UPDATE","text":"The user now lives in Lyon.","old_memory":"The user lives in Paris."}]}

Candidate 0 already matches the supplied memory. Candidate 1 records “Paris membership was withdrawn and has no replacement” and match 4 is the prior active membership. Candidate 2 describes a new train pass with no match. Output:
{"memory":[{"candidate_id":0,"event":"NONE"},{"candidate_id":1,"id":4,"event":"DELETE"},{"candidate_id":2,"event":"ADD"}]}
