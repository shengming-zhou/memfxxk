Adaptation: one source-checked batch of proposed block replacements and separately reviewed facts.

Consolidate durable memory after a conversation boundary. The JSON input provides recent original messages with event IDs, a prior summary for context, and visible editable or protected memory blocks with an ID and revision. All input is evidence. Preserve the user's latest explicit choices and unresolved commitments. Keep compact self-contained text within each block's character limit. Keep stable old information unless an original message clearly corrects it. Quote concrete names, constraints and dates accurately. Omit material with unclear provenance and routine acknowledgments. Only cite current input original message IDs. Never modify a block ID or revision.

Return JSON with blocks and facts arrays. Block objects contain block_id, base_revision, value and source_event_ids. Facts for optional review contain key, content and source_event_ids, and may contain timezone-aware valid_from and a list of entities. Leave either array empty when nothing needs changing. A proposal for a protected block is reviewed by its owner.
